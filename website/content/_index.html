Proving Photos Are Real in the Age of AI

Take a picture. A fingerprint of the file is recorded in a public registry run by journalism organizations. Anyone holding that file can check that it came from a registered camera, and no one can use the registry to find out which camera took it.

The Problem

AI-Generated Images Look Real

Modern AI can create photorealistic images that are indistinguishable from real photographs. How do you know what's real?

Metadata Gets Stripped

Embedded credentials such as C2PA Content Credentials live inside the file. Social media platforms routinely strip that data through compression and format conversion, so the proof is often gone by the time an image reaches its audience.

A Record of Cameras Is a Map of Photographers

A system that links cameras to images is also a map of who photographed what. For journalists, activists and their sources, a breach of that map is exactly the harm a provenance system must not cause.

How It Works (3 Steps)

Step 1: Take a Picture

When the camera saves the image, it computes a "fingerprint" of the file (a SHA-256 hash). It then sends two separate messages along separate network paths: one carries the fingerprint, and the other carries the camera's encrypted credential. Neither message contains the image.

The two messages are joined only by a one-way hash, so no single server that handles them can connect the camera to the picture.

Step 2: Checked, Then Recorded

The camera's manufacturer confirms that the credential belongs to a registered device, without ever seeing the image fingerprint. Independent servers run by consortium members confirm that the two messages belong together. Only then is the fingerprint recorded in the Birthmark Media Registry, a blockchain run by journalism, fact-checking and press freedom organizations.

The record holds no camera, manufacturer or photographer identifier. To make timing harder to trace, messages are deliberately delayed, so a record appears minutes after capture, not instantly.

Step 3: Anyone Can Verify

Anyone with a copy of the file can compute its fingerprint and look it up. A match shows that the file came from a registered device, along with how it was processed and a coarse registration time.

Matching is exact: the copy must be identical to the registered file. An edit made in certified editing software creates a new record linked to the original. A change made anywhere else, including a platform's recompression, produces a file with no record.

Built So a Breach Exposes a Fragment, Not a Map

Servers get compromised. The Birthmark Protocol is designed so that the information needed to link a camera to a picture never comes together in one place, so a breach of any single part of the system doesn't reveal it.

🔒 Two Separate Channels

The image fingerprint and the camera credential travel on separate paths to separate servers. The manufacturer learns which camera is checking in but never sees what it photographed. The servers that handle the fingerprint never see the credential.

🧩 No Single Point of Exposure

For each component of the system, we checked what an attacker holding all of its keys and data could learn. Machine-checked proofs show that no single component can link a camera to a picture. Linking them requires compromising components in different roles at once.

Learn more →

✅ No Single Party Can Forge a Record

A record is written only after two of three independent checkpoints confirm the manufacturer's approval, and two content servers run by different operators submit matching entries. One compromised server, or even two of the three checkpoints, cannot create a false record.

🛡️ Records Live Outside the File

Because the record is kept in the registry and not inside the image, stripping metadata can't remove it. Anyone with an exact copy of the registered file can check it, and certified editing software can link edited versions back to the original.

Current Status

✅ Early Prototype

An early prototype on Raspberry Pi 4 hardware demonstrated the full pipeline, from sensor capture to registry lookup, for an earlier version of the design.

✅ Current Protocol Design

The protocol has since been redesigned around two separate channels, so that no single component can link a device to its content:

  • ✅ Two-channel architecture with separate credential and content paths
  • ✅ Machine-checked privacy proofs (ProVerif) for each component individually
  • ✅ Simulated evaluation of timing and traffic analysis
  • ✅ Compact registry records: 42 bytes per capture

Not yet measured: Device-side costs for the current design are estimated from published benchmarks for the underlying cryptography. Measuring them on real hardware is part of the next phase.

Roadmap: Beyond Photos

The same principles that authenticate photos can extend to other media types:

📹 Video Authentication

Register video at capture so viewers can check that footage came from a registered camera.

Target: Phase 3

🎤 Audio Authentication

Register audio recordings at capture so listeners can check that they came from registered recording hardware.

Target: Phase 3

🖥️ Screenshot Authentication

Show that a screenshot came from a registered device, with a coarse registration time. Useful for documenting online content before deletion.

Target: Phase 4

Immediate Next Steps (Phase 2)

  • Reference implementation: Build the current two-channel design and measure its cost on real camera-class hardware
  • Mobile capture app: Native implementation for photographers (how phones hold their credential is still being specified)
  • User testing: 50-100 journalists and photographers pilot program
  • Developer SDKs: Tools for camera manufacturers and software developers

Why Birthmark Standard?

🔓

Open Source

All code is public. No corporate secrets or proprietary control.

🛡️

Privacy First

Only image fingerprints are stored, never the images themselves. Registry records name no camera, manufacturer or photographer.

🌐

Decentralized

No single company controls the network. Independent journalism and press freedom organizations operate the registry nodes.

💰

No Tokens, No Fees

A permissioned blockchain with no cryptocurrency, no gas fees and no transaction costs.

🤝

Complements C2PA

C2PA carries rich metadata inside the file. Birthmark keeps a record outside it, where metadata stripping can't reach.

⛓️

Stored Outside the File

The record can't be stripped away because it was never in the file. Edits made with certified software stay linked to the original.
